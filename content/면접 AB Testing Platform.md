### 문제

당신은 DAU 50만 모바일 앱의 A/B 테스트 플랫폼을 설계해야합니다.

### 요구사항

- (중요) 유저에게 배정된 그룹은 실험 기간 동안 유지되어야합니다.
- 50개 이상의 동시 실험 지원할 수 있어야 합니다.
- 유저는 여러 실험에 동시 참여 가능합니다.
- 1실험군과 대조군은 최대 10개 그룹까지 존재할 수 있습니다.
- (중요) 각 실험은 서로 영향을 받지 않고 독립적으로 그룹 배정되어야 합니다
- 앱과 서버에서 모두 조회 가능해야합니다.
- 분배 비율은 조건에 따라 다르게 정의할 수 있어야 합니다.
    - 시나리오1) 한국에서만 테스트
    - 시나리오2) 안드로이드 성능 개선 실험을 위해 안드로이드에만 적용
    - 시나리오3) 1.91.0 버젼에서는 보수적으로 90/10 으로 하고 1.92.0 버젼은 모수를 늘려 50/50으로 적용
- A/B 테스트 현황을 모니터링 할 수 있어야하며, 추후 A/B 테스트와 관련된 데이터 분석을 할 수 있어야합니다. (필수사항 아님)

**아키텍처를 화이트보드에 그려주세요**

## 평가항목

|**항목**|**체크포인트**|**점수 (1~5)**|
|---|---|---|
|Bucket 설계 능력|**버킷 배정의 핵심 원칙을 이해하고 있는지 평가합니다.**||

- 유저가 버킷 내에 **균등하게(random-like)** 분포될 수 있는가
    
- 같은 유저는 항상 같은 버킷으로 가는 **deterministic** 특성이 보장되는가
    
- 여러 실험들에 대해 independent 하게 할당되는가
    
- 해시 기반 설계를 선택한 경우
    
    - 적절한 **seed(실험 ID, 오브젝트 ID 등)** 선택 기준을 설명할 수 있는가
    - 사용한 해시 함수(SHA-256 등)의 선택 근거가 명확한가
    - 해시 충돌 발생 시 영향을 이해하고 설명할 수 있는가 | | | 다중 조건 처리 능력 | **분배 비율은 조건에 따라 다르게 정의할수 있게 설계가 되었는가**
- 단일 조건(ex: 앱 버전, OS) 기반 실험 분배 가능
    
- 여부다중 조건(ex: 지역 + OS + 앱 버전) 기반 분배 가능 여부
    
- 조건이 추가되어도 **확장 가능한 구조**인지
    
- 조건 변경 시 기존 사용자에 대한 **deterministic consistency** 유지 여부 | | | 구현 완성 능력 | **프로덕션 환경에서 사용가능한 수준까지 설계 되었는지를 평가합니다.**
    
- 실제로 유저가 실험값을 받을 수 있게 되었나.
    
- 언제든지 실험을 on/off 할 수 있는 구조로 설계되었는가
    
- 여러개의 실험값을 받을 수 있게 설계되었는가
    
- 서버와 클라이언트가 일관된 값을 가지고 사용할 수 있나 | | | 시스템 및 확장 설계 능력 | **트래픽이 늘어났을 때, 안정적으로 서빙할 수 있는지 평가합니다.**
    
- 트래픽이 늘어날 때, 선형적으로 자원이 소비되지는 않은가
    
- cdn이나 캐싱을 적극적으로 사용하는가
    
- 멀티 인스턴스 환경에서 idempotent하고 deterministic한 결과가 나오는가
    
- 실험 데이터 로딩이 앱 cold start를 지연시키지 않는가 | | | 기술 의사결정 능력 & 커뮤니케이션 능력 | **구현을 하는 도구를 선택할 때 기술적 근거로 합리적으로 의사결정하는지 평가합니다. 그 과정 속에서 커뮤니케이션 능력을 평가합니다.**
    
- DB / S3를 저장소로 사용하는 이유
    
- 특정 해시 함수를 사용하는 이유
    
- 인터뷰어의 질문에 근거를 들어 설명하고, 모르는 부분은 솔직히 인정하는지 등을 종합적으로 평가 | |

### 기본 질문 리스트

- DB vs 파일 기반의 장단점은 뭘까요?
- 만약 특정 유저만 실험값을 override 하고 싶다는 니즈가 있는 경우는 어떻게 하나요?
- 같은 사용자가 항상 같은 그룹에 들어가도록 어떻게 보장하나요?
    - Random 대신 Hash를 사용하면 어떤 이점이 있나요?
    - user_id만 해시하면 모든 실험에서 같은 그룹이 되는데, 어떻게 해결하나요?
    - 해시 함수는 무엇을 사용하시겠어요? 그 이유는?
- 실험 중간에 50:50에서 70:30으로 바꾸면 기존 사용자 그룹이 바뀌나요?
- 매번 서버에서 설정을 가져오면 부하가 생길텐데, 어떻게 하시겠나요?
    - 모범답변
        
        ```
        CDN (CloudFront) - 기본 캐시 + 수동 무효화
             ↓
        서버 메모리 - 30초 TTL (memoization)
             ↓
        클라이언트 - 5분 주기 갱신
        ```
